KV Cache 量化：最强进展，分赛道看

低比特 cache 已从“统一缩放再量化”走向结构感知：MLA 的双路径校准、RoPE 通道对敏感度、数据自适应变换，以及真正融合进 attention 的低比特内核。压得更小不自动等于跑得更快。

先说判断

没有一个普适的 KV 量化冠军。 MLA 看 RoLaQ / QuantMLA；普通 RoPE key cache 看 PN-Mix；冲击 1-bit VQ 看 TaSQ；想看内核端的 decode 上限，看 FuTransformer。所有吞吐数字都要连同模型、GPU、上下文和 workload 一起读。

核心：冻结模型权重，对 MLA latent 的共享旋转与量化范围做联合离线校准，用 prediction matching 和 attention-output supervision 约束误差。

边界：只适用于 MLA latent cache 路径，不能直接外推到标准 MHA/GQA。吞吐是单一模型与上下文设置的论文自报结果，非统一复现榜单。

PN-MixPair-Norm Guided Mixed-Precision Key CacheRoPE · 2.26-bit avg2026-10-14较低平均 bit 下维持 / 改善任务准确率

核心：在 RoPE channel-pair 粒度分析 attention-logit 扰动；prefill 时按 query–key pair-norm 找出敏感通道对，decode 期间复用混合精度分配。

证据：作者报告在 reasoning、code generation、AIME 上，2.26-bit 平均精度可比或高于 2.32–2.39 bit 的既有 mixed-precision 方法；Pareto sweep 在 1.5 bit 仍较平缓。

边界：主要贡献是准确率 / 平均 bit Pareto，不是端到端时延结果。依赖 RoPE decoder-only 模型以及 prefill 的 query 统计。

TaSQTailoring the Quantization SpaceVQ · 1-bit 路线2026-10-02RTX 6000 Ada：最多 14× batch · 1.87× peak throughput

核心：query-guided channel weighting、cross-head normalization、covariance-aware channel grouping，改造 1-bit VQ 目标空间，且变换可折叠进投影和 codebook。

证据：论文覆盖通用任务、长链推理与长上下文检索；报告 SGLang 单卡 RTX 6000 Ada 上最多 14× batch capacity 和 1.87× peak throughput（相对 BF16）。

边界：吞吐峰值和 batch 倍数属于作者硬件/实现配置。实际收益取决于 VQ lookup 与 attention kernel 是否命中目标 workload。

论文 / arXiv v1
QuantMLAFunction-Aligned Dual-Path QuantizationMLA · INT4 / INT2+INT42026-09-29 · v2128K：3.59× physical compression · 特定 workload 5.168×

核心：分别对 MLA content 与 RoPE positional path 做 function-aligned 变换与量化目标；低比特 unpack/dequant 融入原生 MLA attention kernel。

证据：作者报告四类 MLA 模型上 joint INT4，或 content INT2 + RoPE key INT4 的结果；128K physical cache compression 3.59×，cache-pressure whole-job output throughput 5.168×。

边界：5.168× 是 cache-pressure 整体作业吞吐，不是普遍 decode 加速。该版本摘要写明代码将在接收后发布，独立复现状态较弱。

WUSH-KVData-Adaptive TransformsRoPE · 2-bit2026-09-29SGLang：2-bit 下与 OSCAR 相当或更优

核心：用校准数据估计矩阵乘数两侧的二阶统计，分别为 key、value 构造变换；value 变换折叠进模型权重，key 变换放在 RoPE 之后。

证据：论文报告在 SGLang 中以 OSCAR-style percentile clipping 做端到端评测，2-bit 下跨所测模型和下游任务达到与 OSCAR 相当或更好的结果。

边界：摘要未提供一个可横向比较的吞吐 headline。更适合作为减少量化误差的算法变换结果，而非 serving SOTA 宣称。

FuTransformerFused Hopper low-bit inference kernelHopper · INT4 KV2026-10-16Llama-3.1-8B：2.8 ms/token step vs 8.1 ms

核心：把 INT4 权重与 KV 解量化直接嵌入 Tensor Core MMA operand layout；块对角 Hadamard transform 缓解 cache outlier channel 误差。

证据：单 H100 上，论文报告完整 Llama-3.1-8B decode 为 2.8 ms/step，对比 compiled Transformers 的 8.1 ms；旋转 INT4 cache 在其 WikiText-2 设置中增加 0.20 perplexity。

边界：总体速度提升同时包含 kernel、INT4 projection weights 和 KV cache 改动，不能把全部差异归因于 cache 量化。硬件限定为 NVIDIA Hopper。

03 / Capacity model

显存估算器

先算 KV payload 的理论下限，再拿真实 serving profile 验证物理占用。

输入模型与上下文

原始 KV payload；支持 GQA 的 KV head 数。

当前精度估算4 GiB
同配置 BF16 基准4 GiB

公式：2 × 层数 × batch × context × KV heads × head dim × bits ÷ 8。采用二进制 GiB。默认示例：32 层、32K、8 KV heads、128 dim，BF16 = 4 GiB，INT2 = 512 MiB。

解读时记住

有效 bit ≠ 物理 cache 字节。

  • KV heads：GQA/MQA 的 KV heads 少于 query heads，按实际 KV heads 填。
  • 非整字节精度：2.26-bit 这类平均值需要 scale、分组与打包元数据；这里只算理想 payload。
  • MLA：latent cache 维度不是普通 K/V 的 `2 × heads × head_dim`，不要把这个结果套到 MLA。
  • 总显存：还要加权重、workspace、CUDA graph、block/page 对齐、scale/codebook 和 allocator 碎片。
  • 带宽：实际提速看 fused kernel 是否能边读边解量化，以及 decode 是否真被 cache 带宽限制。
04 / Practical read

从论文到部署：先验证这些

不要把 paper headline 当成产品承诺。“容量提升”“单步 decode 变快”“整作业吞吐提升”是三种不同指标。上表中的模型结构、上下文长度、GPU、batch、baseline 和是否同时量化权重都不相同。

最新的系统侧补充（2026-10-20）不是量化新算法：本地长上下文推理分析指出 self-attention 会主导长上下文运行时间，同时 paging、cache utilization 与同步仍存在系统瓶颈。这意味着压缩率只是容量一环，未必自动提高 tokens/s。查看论文

如果你要选路线

  • DeepSeek MLA：优先做 RoLaQ 与 QuantMLA 的同模型、同 SGLang 版本对照，检查质量和物理 cache layout。
  • Llama/Qwen 等 RoPE MHA/GQA：先比 PN-Mix / WUSH-KV 的质量–bit 曲线；若目标是 1-bit，再评估 TaSQ 的 codebook/kernel 成本。
  • H100 decode 瓶颈：复现 FuTransformer 时把权重量化、cache 量化、kernel 融合分开消融，否则归因不清。

最小复现清单

  • 固定模型 checkpoint、tokenizer、RoPE 设置和任务集，报告量化校准数据。
  • 同一 prompt 与生成参数，比较任务准确率、perplexity、长输出稳定性，不只看局部重建误差。
  • 报告有效 bit 与实际分配字节；分别测 prefill、decode、不同 batch/context 的 tokens/s 和峰值显存。
  • 至少做精度分配、transform、kernel 三项消融，并记录代码 commit、CUDA、驱动、GPU 型号。
